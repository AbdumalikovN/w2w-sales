# W2W CRM

CRM отдела продаж Win to Win в стилистике сайта w2w.uz: воронки, карточки клиентов со всей историей, проекты в работе по этапам разработки, аналитика «что работает в продажах», база анкет курса «ISAEV Dastur 24». Заменяет Notion CRM (Sales → CRM, архив, Logistics, Catering) и прежний зашифрованный дашборд.

**Рабочий адрес:** https://w2w-crm.netlify.app (старый адрес abdumalikovn.github.io/w2w-sales перекидывает туда).

## Что внутри

| Раздел | Что делает |
|---|---|
| Сегодня | «Ждут нашего ответа», новые лиды, встречи, кому позвонить, зависшие и просроченные шаги, отчёт синхронизации |
| Воронка | Канбан по статусам для каждой воронки (Продажи AI, Логистика, Кейтеринг, Архив 2025), перетаскивание, фильтры |
| Сделки | Реестр с фильтрами, массовыми действиями и выгрузкой CSV |
| Проекты | Клиенты с договором по этапам разработки: бриф → аналитика → дизайн → разработка → тесты → приёмка → сдан → поддержка |
| Аналитика | Воронка, конверсии, форматы касания, источники, отрасли, регионы, причины отказов, команда |
| База курса | Анкеты группы курса, кому ещё не писали; карточка создаётся в один клик |
| Настройки | Пользователи и роли, токены интеграций, справочники и воронки, выгрузка данных, корзина (только администратор) |

Карточка клиента: контакт, контекст клиента, следующий шаг и срок, встреча, классификация, контакты, этапы сделки и документы (чек-листы), ссылки, договорённости, заметки со встреч, риски, проект и сумма, история переписки и всех изменений. Правки сохраняются сами; если двое меняют одно поле одновременно, CRM предупредит и не затрёт чужое.

Роли: **администратор** (всё + пользователи и справочники), **менеджер** (ведёт сделки), **наблюдатель** (только смотрит). Вход по личному логину и паролю; при первом входе пароль нужно сменить.

## Как устроено

```
браузер ──► w2w-crm.netlify.app ──┬─► /api/*  → Netlify Function (netlify/functions/api.mts) → Netlify Blobs
                                  └─► всё остальное → прокси на GitHub Pages (index.html, assets/)
Claude (вечерняя синхронизация Telegram) ──► /api/sync/* с токеном интеграции
```

- **Интерфейс** — статические файлы без сборщика: `index.tpl.html`, `assets/css/crm.css`, модули `assets/js/*.js`. Публикуется на GitHub Pages workflow «Интерфейс CRM → GitHub Pages» при каждом push в `main`, который меняет интерфейс.
- **API** — одна функция `netlify/functions/api.mts`, маршруты в `netlify/lib/routes.mts`, схема полей и статусы в `netlify/lib/model.mts`, правила синхронизации в `netlify/lib/sync.mts`.
- **Данные** — Netlify Blobs (хранилище `crm`): `db` — сделки и справочники, `users` — пользователи и токены, `h/<id>` — история карточки, `base` — анкеты курса, `backup/<дата>` — ежедневная копия (хранятся 45 дней), `config` — служебный ключ подписи сессий.
- **Безопасность** — пароли в scrypt, сессия в HttpOnly-куке с подписью HMAC, защита от CSRF, ограничение попыток входа, токены интеграций хранятся только как хеш. Ключ подписи сессий сервер создаёт сам и держит в хранилище — он не виден ни в коде, ни в настройках Netlify.

### Переменные окружения Netlify (Project configuration → Environment variables)

| Переменная | Зачем |
|---|---|
| `SETUP_KEY_SHA256` | SHA-256 ключа первичной установки — нужен один раз, чтобы создать первого администратора (`POST /api/auth/setup` с заголовком `x-setup-key`). Пока в CRM есть хотя бы один пользователь, установка закрыта |
| `CRM_SECRET` | необязательно: свой ключ подписи сессий (≥ 32 символов) вместо автоматического. Смена ключа = выход всех пользователей |

Проверка: `https://w2w-crm.netlify.app/api/health` → `configured.secret` (`store` или `env`) и `configured.setupKey: true`.

## Деплой и кредиты Netlify

Проект на бесплатном тарифе Netlify: 300 кредитов в месяц, при исчерпании сайт останавливается до следующего месяца. Production-деплой стоит 15 кредитов, поэтому:

- **Правки интерфейса** (`index.tpl.html`, `assets/`) — просто push в `main`. GitHub Pages опубликует их бесплатно, Netlify деплоить не нужно. Обновление доходит до пользователей в течение ~10 минут (кеш GitHub Pages).
- **Правки API** (`netlify/`, `netlify.toml`) — нужен деплой Netlify (`netlify deploy --prod` или через Claude). Делайте их пачкой.
- Обычная работа двух-трёх человек укладывается в бесплатный лимит с большим запасом. Если команда вырастет или понадобится больше деплоев — тариф Personal.

## Синхронизация Telegram → CRM

Каждый день в 18:57 по Ташкенту запланированная задача Claude читает переписку @ceo_w2w (только чтение, клиентам ничего не отправляется) и вызывает API с токеном интеграции (Настройки → Интеграции):

- `GET /api/sync/index` — компактный список карточек для сопоставления чатов;
- `POST /api/sync/apply` `{items, dryRun}` — создать/обновить карточки и историю;
- `POST /api/sync/report` `{text, stats, ok}` — отчёт, его видно на «Сегодня» и в меню слева.

Правила, которые соблюдает сервер (а не только скрипт): ручные статусы (ТЗ, КП, Продажа, В ожидании, Договор, Успешные, Архив) синхронизация не меняет; автоматически статус двигается только вперёд по цепочке Потенциальные → Изучение → Назначили встречу; ответственного и воронку не трогает; контакты и риски только дописываются; история не дублируется. Заголовок `Authorization: Bearer w2wk_…`.

## Перенос из Notion

Сделан 24.10.2026: 189 карточек основной CRM (свойства + тело страницы, разобранное по разделам шаблона), 116 карточек «CRM (Архив)» → воронка «Архив 2025» (2 пустые карточки без названия пропущены), 73 карточки Catering, 1 Logistics, 618 записей истории переписки, 75 анкет курса. Notion остаётся архивом только для чтения; новые данные идут только в CRM.

Скрипты (данные клиентов в репозиторий не кладутся):

- `scripts/notion_to_crm.py --crm <выгрузка> --archive … --catering … --logistics … --base … --out пакет.json` — преобразование выгрузки в пакет импорта;
- `CRM_LOGIN=… CRM_PASSWORD=… OWNER_MAP='{"notion:<id>":"<логин>","*":"<логин>"}' MODE=merge node scripts/import_to_crm.mjs пакет.json https://w2w-crm.netlify.app` — загрузка (`MODE=replace` полностью заменяет сделки).

## Локальная разработка

```
npm install
npm test                     # тесты API
npm run dev                  # http://localhost:8787, данные в dev/.data
STATIC_DIR=_site npm run dev # проверить собранную для Pages версию (после npm run build)
```

Первый администратор локально: `curl -X POST localhost:8787/api/auth/setup -H 'x-setup-key: dev-setup-key-dev-setup-key-0001' -H 'content-type: application/json' -d '{"login":"admin","name":"Админ","password":"длинный-пароль"}'`.

## Резервные копии и выгрузка

- Ежедневно при первой записи дня сервер сохраняет копию базы (`backup/<дата>`, 45 дней).
- Настройки → Данные и корзина → «Скачать JSON»: сделки, история, анкеты и список пользователей (без паролей).
- Удалённые карточки попадают в корзину, оттуда администратор их восстанавливает.
